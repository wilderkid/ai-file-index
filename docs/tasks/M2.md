# M2 — NTFS 全量枚举（FSCTL_ENUM_USN_DATA）

## 目标
在 `aifi-ntfs` 中实现 `NtfsVolume: VolumeSource` 的 `open` / `info` / `enumerate` 和 `list_ntfs_volumes`，
以**只读**方式在数秒内枚举整个 NTFS 卷的所有文件名与父子关系。

## 背景
- Everything / Listary 的速度来自直接读 MFT：`DeviceIoControl(FSCTL_ENUM_USN_DATA)` 一次返回一批 `USN_RECORD_V2/V3`，
  每条含 FRN、父 FRN、属性、文件名（UTF-16），无需逐目录遍历。
- 需要管理员权限打开 `\\.\C:`（`CreateFileW`，`GENERIC_READ`，共享 `FILE_SHARE_READ | FILE_SHARE_WRITE`）。
- 先 `FSCTL_QUERY_USN_JOURNAL`（0x900F4）拿 `UsnJournalID` 与 `NextUsn`，作为 `JournalCursor`；**日志不存在时不要创建**，
  返回 `Error::Platform("usn journal not active")`，由服务层决定退化方案。
- 骨架：`crates/aifi-ntfs/src/win.rs` 中 `NtfsVolume` 结构、`Drop`、`ioctl` 常量、`reason::classify` 已就位。
  依赖：`windows = 0.62.2`（features 已在 Cargo.toml 中）。
- 记录格式：`MFT_ENUM_DATA_V1 { StartFileReferenceNumber, LowUsn: 0, HighUsn: NextUsn, MinMajorVersion: 2, MaxMajorVersion: 3 }`；
  输出缓冲区前 8 字节是下一个起始 FRN，其后是变长记录（`RecordLength` 对齐 8）。V3 使用 128 位 FRN，v1 只取低 64 位并记录。

## 要改的文件
- `crates/aifi-ntfs/src/win.rs`（主要）
- `crates/aifi-ntfs/src/lib.rs`：新增纯函数 `parse_usn_records(buf: &[u8]) -> impl Iterator<Item = Result<RawUsnRecord>>`，
  **平台无关**，以便在 Linux 上用字节 fixture 测试。
- `crates/aifi-ntfs/tests/fixtures/*.bin`（手工构造的记录缓冲区）
- `scripts/ci-create-vhd.ps1`（新增，仅在 CI 中创建临时 VHD）+ `.github/workflows/ci.yml` 启用 `ntfs-vhd` job

## 接口
```rust
pub struct RawUsnRecord { pub frn: u64, pub parent: u64, pub usn: i64, pub reason: u32, pub attributes: u32, pub name: String }
pub fn parse_usn_records(buf: &[u8]) -> impl Iterator<Item = Result<RawUsnRecord>>; // 全平台
#[cfg(windows)] impl NtfsVolume { pub fn open(id: VolumeId, mount: &str) -> Result<Self>; }
#[cfg(windows)] impl VolumeSource for NtfsVolume { fn info(..); fn enumerate(..) -> Result<JournalCursor>; }
#[cfg(windows)] pub fn list_ntfs_volumes() -> Result<Vec<String>>;   // GetLogicalDriveStringsW + GetVolumeInformationW，仅 DRIVE_FIXED + NTFS
```

## 验收标准 / 测试
- [ ] `parse_usn_records` 在 Linux 上通过：V2、V3、截断缓冲区、`RecordLength` 越界、非法 UTF-16（用 U+FFFD 替换并计数）。
- [ ] 缓冲区 64 KiB 起步，循环直到 `ERROR_HANDLE_EOF`；所有错误路径都关闭句柄（RAII）。
- [ ] Windows CI：在临时 VHD（如 `X:`）上创建 1 万个文件（含中文名、深层目录），枚举结果与 `std::fs` 遍历一致。
- [ ] 在开发者自己的 C: 上手动测量：条目数、耗时（目标 100 万文件 < 3 s）、峰值内存，贴到 PR。
- [ ] `cargo check --target x86_64-pc-windows-gnu` 和 Linux `cargo test` 均通过。

## 不在范围内
USN 增量读取（M3）、快照（M3）、非 NTFS 卷、服务封装（M6）。

## 审查清单
- [ ] 只用了 `ENUM_USN_DATA` / `QUERY_USN_JOURNAL` / `GET_NTFS_VOLUME_DATA`；**没有** `CREATE_USN_JOURNAL` / `DELETE_USN_JOURNAL` / 任何写 IOCTL
- [ ] 句柄只读打开，`Drop` 中 `CloseHandle`
- [ ] 所有 `unsafe` 有 `// SAFETY:`，缓冲区解析全部做边界检查（解析在安全代码中完成）
- [ ] 集成测试只在 VHD 上跑，未触碰系统盘
- [ ] PR ≤ ~400 行（解析器 / 枚举 / CI 可分开）
