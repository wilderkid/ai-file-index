# M9 — 真正的 Windows 服务生命周期与安装包

## 目标
`sc start AiFileIndex` 能正常启动并报告 Running；停止时 5 s 内写完快照退出；开机自动（延迟）启动；崩溃后 SCM 自动重启；
MSI 能安装、升级、卸载，升级时不会因 `aifi-mcp.exe` 被 AI 会话占用而失败。

## 背景
- 现状：`service_main` 直接调用 `run_console()`，从不向 SCM 报告状态，`sc start` 超时（错误 1053）。
- 依赖：`windows-service 0.8.1`（`service_control_handler::register`、`ServiceStatus`、`ServiceControl::Stop/Shutdown/Preshutdown`）。
- `installer/aifi.wxs` 仍是占位。

## 要改的文件
- `crates/aifi-service/src/main.rs`：`serve()` 接收 `shutdown: tokio_util::sync::CancellationToken`（或 `tokio::sync::watch`），
  控制台模式由 Ctrl-C 触发，服务模式由 SCM 控制事件触发。
- `crates/aifi-service/src/win/service.rs`（新）：注册控制处理器 → `StartPending` → 索引开始构建即报 `Running`
  （查询在 building 状态返回 `NotReady`）→ 收到 Stop 报 `StopPending`（带 `wait_hint`）→ 写快照 → `Stopped`。
- `installer/aifi.wxs`：WiX v5，`ServiceInstall`（LocalSystem、`DelayedAutoStart`、`ServiceConfigFailureActions` 重启 ×3）、
  `ServiceControl`（安装启动、卸载停止并删除）、`%ProgramData%\AiFileIndex` ACL（SYSTEM + Administrators）、`MajorUpgrade`。
- `installer/README.md`、`docs/setup.md`：安装、升级、排错。
- `README.md`：去掉"骨架阶段"，写明当前能力与限制。
- `.github/workflows/ci.yml`：Windows 作业 `wix build` 产出 MSI 工件（不发布）。

## 升级时 aifi-mcp.exe 被占用
MSI 遇到占用文件会要求重启。做法：安装 `aifi-mcp.exe` 时设 `MsiFileInUse` 提示，并在文档中说明"升级前关闭 AI 会话"；
不做自动结束进程。若实践中仍频繁遇到，再评估把 MCP 端拆成"启动器 + 版本目录"。

## 验收标准 / 测试
- [ ] 一次性虚拟机中：安装 → `sc query` 为 RUNNING → `sc stop` 5 s 内 STOPPED 且快照文件更新 → 再次启动走快照。
- [ ] 结束进程（任务管理器）后 SCM 在 60 s 内重启服务。
- [ ] 卸载后服务与 `%ProgramData%\AiFileIndex` 都不存在；不触碰用户文件与 USN 日志。
- [ ] `--console` 模式行为不变，Ctrl-C 也会写快照。
- [ ] CI 产出 MSI 工件。
