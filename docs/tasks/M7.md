# M7 — MCP 服务器、Claude Code / Codex 接入、安装包占位

## 目标
`aifi-mcp.exe`（普通用户、stdio）把 5 个 MCP 工具调用转发到服务并返回结构化结果；提供 Claude Code / Codex 一键接入说明；
产出可构建的 MSI（WiX）草稿。

## 背景
- 骨架：`crates/aifi-mcp`：`tools.rs`（5 个 `ToolDef`，schema 由 `schemars::schema_for!` 从 `aifi-protocol` 参数类型生成，`INSTRUCTIONS`）、
  `server.rs`（`AifiMcp: rmcp::ServerHandler`，`get_info` / `list_tools` 已实现，`call_tool` 为 `todo!("M7")`）、
  `ipc_client.rs`（`IpcClient::connect` / `call` 为 `todo!`）、`main.rs`（stdio 服务、`--print-tools`）。
- 依赖：`rmcp 3.8.0`（features `server`, `transport-io`），`tokio 1.54.1`。rmcp 3.8 API：
  `call_tool(CallToolRequestParams, RequestContext<RoleServer>) -> Result<CallToolResponse, McpError>`。
- 工具：`find_files`、`list_project_tree`、`list_projects`、`recent_changes`、`index_status`。
- 接入命令：`claude mcp add --scope user --transport stdio ai-file-index -- <path>\aifi-mcp.exe`；
  `codex mcp add ai-file-index -- <path>\aifi-mcp.exe` 或 `~/.codex/config.toml` 的 `[mcp_servers.ai-file-index]`。

## 要改的文件
- `crates/aifi-mcp/src/server.rs`：`call_tool`（参数反序列化 → `Request` → IPC → 结果），同时返回 `structuredContent` 与简洁文本。
- `crates/aifi-mcp/src/ipc_client.rs`：连接（`ERROR_PIPE_BUSY` 重试）、hello 握手、请求超时 10 s、断线重连一次。
- `crates/aifi-mcp/src/main.rs`：移除 `#[allow(dead_code)]`。
- `README.md`、`docs/setup.md`（新）：Claude Code / Codex 配置、排错（服务未运行、版本不符）。
- `installer/aifi.wxs`、`installer/README.md`：补全 GUID、ProgramData 目录与 ACL、卸载清理；CI 中 `wix build` 产出 MSI 工件（不发布）。

## 接口
```rust
impl IpcClient {
    pub async fn connect() -> anyhow::Result<Self>;                     // 含 hello，记录服务 capabilities
    pub async fn call(&mut self, req: Request) -> anyhow::Result<Response>;
}
impl ServerHandler for AifiMcp { async fn call_tool(&self, p: CallToolRequestParams, cx: RequestContext<RoleServer>) -> Result<CallToolResponse, McpError>; }
fn request_from_tool(name: &str, args: serde_json::Value) -> Result<Request, McpError>;  // 纯函数，全平台可测
fn render_text(resp: &Response) -> String;                                              // 纯函数，给 AI 的紧凑文本
```

## 验收标准 / 测试
- [ ] `request_from_tool`：5 个工具的合法参数、缺失必填、未知工具、`limit` 超界（被截断）测试，Linux 可跑。
- [ ] `render_text`：输出紧凑（每条命中一行：路径 + 类型 + 匹配方式），50 条结果 < 4 KB。
- [ ] 服务未运行时返回清晰的 MCP 错误（含"请启动 AiFileIndex 服务"），不 panic、不挂起。
- [ ] 用 rmcp 客户端写端到端测试：内存中的假 IPC 服务端 + stdio 管道，`tools/list` 返回 5 个工具，`tools/call find_files` 返回结果。
- [ ] Windows 手动验证：Claude Code 与 Codex 中各执行一次 `find_files`（截图或日志贴 PR）。
- [ ] MSI 能在 CI 构建；安装/卸载只在一次性虚拟机中测试。

## 不在范围内
自动修改用户的 Claude/Codex 配置文件（只打印命令）；内容搜索；自动更新；任何网络功能。

## 审查清单
- [ ] `aifi-mcp` 不直接读盘、不提权、不联网
- [ ] 工具描述准确，不诱导 AI 绕过黑名单
- [ ] 错误信息不泄露被黑名单过滤的路径
- [ ] stdout 只输出 MCP 协议数据，日志全部走 stderr
- [ ] 安装包卸载时清理服务与 ProgramData，不触碰用户文件 / USN 日志
- [ ] PR ≤ ~400 行（ipc_client / call_tool / 文档 / 安装包 分开）
