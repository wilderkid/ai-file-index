# M8 — 服务内的增量更新、快照与 recent_changes

## 目标
服务启动后索引持续保持最新：文件创建/删除/重命名/移动后 < 1 s 可搜到；`recent_changes` 返回真实变更；
服务重启时从快照恢复并追上停机期间的变化，不再每次全盘枚举。

## 背景
- M3 已有：`NtfsVolume::read_changes`（非阻塞，`BytesToWaitFor: 0`）、`catch_up`、`open_or_rebuild`、`FileSnapshotStore`。
- M6 已有：`Handler`（借用 `&[VolumeIndex]`）、`RecentLog`（未接线，`#[allow(dead_code)]`）。
- 现状：`serve()` 只调用 `build_index`，索引建好后不再变化；`Handler::new` 未带 `RecentLog`，`recent_changes` 恒为 `NotReady`。
- 已知缺陷：`parse::to_change_event` 把 `usn` 当作 `timestamp`。USN 记录自带 `TimeStamp`（FILETIME，V2 偏移 32，V3 偏移 48）。

## 要改的文件
- `crates/aifi-ntfs/src/parse.rs`：`RawUsnRecord` 增加 `timestamp`（FILETIME → Unix 秒）；`to_change_event` 使用它。
- `crates/aifi-service/src/state.rs`（新）：`ServiceState { volumes: Vec<RwLock<VolumeSlot>>, recent: Mutex<RecentLog>, … }`，
  `VolumeSlot { index, cursor, state: VolState, last_change }`；平台无关，用假卷测试。
- `crates/aifi-service/src/follow.rs`（新）：`poll_volume(src, slot, recent, deny)` 纯逻辑：读一批变更 → 写锁内 `apply`
  → 记录 recent（**路径在写锁内、apply 前后分别取**，删除前取旧路径）→ 遇 `JournalReset` 在锁外全量重建后替换。
- `crates/aifi-service/src/main.rs`：每卷一个线程循环 `poll_volume` + 空闲时 sleep（250 ms）；启动用 `open_or_rebuild`；
  定时（10 分钟）与 Ctrl-C / 停止时写快照到 `%ProgramData%\AiFileIndex\`。
- `crates/aifi-service/src/handler.rs`：从 `ServiceState` 取读锁构造；`index_status` 报告 `state`、`last_usn`、`snapshot_age_secs`。

## 验收标准 / 测试
- [ ] 假卷：`poll_volume` 处理创建 / 删除 / 重命名 / 目录移动后，`find_files` 结果与重新枚举一致。
- [ ] 假卷 `reset_journal` / `truncate_journal` → 该卷状态变 `rebuilding` → 重建后 `ready`，其他卷查询不受影响。
- [ ] `recent_changes`：创建、删除（报告旧路径）、重命名（带 `old_path`）都有记录；黑名单路径不出现；`since` 生效。
- [ ] `to_change_event` 的时间戳是 Unix 秒（手工构造 FILETIME 测试）。
- [ ] 快照：服务第二次启动走 `FromSnapshot`（日志里可见），冷启动 < 1 s（贴数据）。
- [ ] 写锁持有时间：一批 ≤ 4096 条变更，单批 apply < 50 ms。

## 不在范围内
SCM 服务生命周期（M9）、元数据补全（M10）、非 NTFS 卷。

## 审查清单
- [ ] 只用 `FSCTL_READ_USN_JOURNAL` / `FSCTL_QUERY_USN_JOURNAL`，不创建/删除日志
- [ ] 快照目录只由服务写，路径不来自客户端
- [ ] 重建在锁外进行，查询期间不阻塞
- [ ] recent 写入前过黑名单
- [ ] PR ≤ ~400 行（timestamp 修复 / state+follow / 接线+快照 分开）
