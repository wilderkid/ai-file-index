# M11 — v2：内容搜索

## 目标
新工具 `search_content`：文件名索引先缩小候选集，再读文件内容找匹配行，返回 `路径:行号: 内容`。
先支持纯文本（UTF-8 / UTF-16 / GBK），docx / xlsx / pdf 文本提取留到下一步。

## 决定：谁来读文件（2026-10-31 人类确认）

服务以 SYSTEM 运行。如果由服务替调用方读内容，任何能连上管道的普通用户都能读到自己 ACL 不允许读的文件。
**由 `aifi-mcp` 以调用者身份读**：它本来就以启动它的用户身份运行，普通只读打开时 Windows ACL 自然生效。
服务保持"只看元数据、从不读内容"。AGENTS.md 第 2 节与 `docs/privacy.md` 已相应更新。

不采用的方案：服务端 `ImpersonateNamedPipeClient` 模拟调用方——模拟代码易出错，且读文件期间服务线程以用户身份运行。

## 实现

- `crates/aifi-mcp/src/content.rs`：参数、解码、匹配、片段、上限、`read_file`。纯逻辑通过回调读盘，可在任何平台测试。
- `crates/aifi-mcp/src/server.rs`：`search_content` → 分页调用服务的 `find_files`（`kind=file`、`max_size=1 MiB`）
  取候选 → `spawn_blocking` 里扫描。
- `aifi-protocol::FindFilesParams.require_project`（`#[serde(default)]`）：`cwd` 不在项目里时报错，而不是退回整盘。
- 服务：`scope=project` 改为只扫描项目根子树（原来扫全卷再按分层丢弃）。
- `aifi-project::ProjectRoots`：按祖先目录查哈希集合判断"在不在某个项目里"，与项目数量无关。

## 安全规则

- 必须给出 `under` 或位于已识别项目内的 `cwd`；不支持整盘逐个读文件。`under` 命中黑名单直接拒绝。
- 候选已由服务过黑名单；读之前再用 `Denylist::is_denied` 检查一次，命中的文件从不打开（测试证明）。
- 以 `FILE_FLAG_OPEN_REPARSE_POINT | FILE_FLAG_OPEN_NO_RECALL` 打开，按句柄属性跳过重解析点与云端占位文件，
  不跟随链接、不触发 OneDrive 下载；没有"先检查后打开"的竞态。
- 含 NUL 的文件按二进制跳过。上限：单文件 1 MiB、总读取 64 MiB、候选 2000 个、每文件 5 行、匹配 50 行（≤ 500）、5 s。
- 内容不发给服务、不进索引 / 快照 / 日志；只有命中行片段（≤ 200 字符）返回给 AI。

## 实测（2026-10-31，本机）

| 调用 | 结果 |
|---|---|
| 仓库内字面量（`cwd` 项目，`*.rs`） | 9 处 / 4 个文件，扫描 65 个文件，17 ms |
| `docs` 下中文"黑名单" | 39 处 / 12 个文件，9 ms |
| 正则 `PROTOCOL_VERSION: u32 = \d+` | 1 处，扫描 109 个文件，25 ms |
| 本机一个业务文档目录（xlsx / pdf / rar） | 16 个二进制跳过，37 ms |
| `under=E:\`、无文件名过滤 | 检查前 2000 个候选后停止并说明，1.4 s |
| 无 `under` / `cwd` 不在项目 / `under` 在黑名单 | 均明确拒绝 |

真机测试暴露的性能问题（已修）：`under=E:\` 的候选查询原来要 15 s，原因是每条命中都和 999 个项目根逐个比较。
改用 `ProjectRoots` 后 0.63 s；合成基准 200 万命中 × 1000 个根从 14.8 s 降到 4.4 s（剩余开销是为每条命中拼路径，
见 M10 遗留）。

## Office 文档（2026-10-31 完成）

docx / xlsx / pptx 在 `crates/aifi-mcp/src/office.rs` 里提取文字。没有用 `zip` + `quick-xml`：这两个库带来大量
不需要的功能（`zip` 默认启用加密与七种压缩算法），这里只需要读中央目录、stored / deflate 解压和取文字节点，
自己实现约 300 行，唯一新依赖是 `miniz_oxide 0.9.1`（MIT/Zlib/Apache-2.0，Rust 标准库与 flate2 都在用的
纯 Rust deflate 实现）。

- Word：正文，然后页眉、页脚、脚注、批注；按段落断行。PowerPoint：按幻灯片编号顺序。
  Excel：按工作簿里的工作表顺序，每行一行（单元格制表符分隔），共享字符串与内联字符串都解析，跳过注音。
- 结果带位置：`报价!12`（工作表!行号）、`slide 3`。
- 防 zip 炸弹：条目 ≤ 2 万，单条解压后 ≤ 16 MiB，整包 ≤ 48 MiB，文字 ≤ 8 MiB；单文件读取上限 16 MiB；
  调用总预算按提取后的文字计。zip64、加密、其他压缩方式直接放弃该文件（`Unsupported`）。
  测试覆盖截断与逐字节翻转的输入，均不 panic。
- 实测：本机一个业务文档目录里搜一个料号，37 个文件里 15 个命中（含一个 xlsx 的 `Sheet1!6`），27 ms；
  另一个文档目录下 xlsx/docx/pptx 搜 `total`，扫描 99 个文件 170 ms。
- 片段脱敏已做（`redact.rs`，不可关闭）。
