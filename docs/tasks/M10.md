# M10 — 元数据（大小、修改时间）与查询过滤

## 目标
命中结果带文件大小与修改时间；`find_files` 支持按目录、大小、时间过滤并按修改时间排序，
让 agent 能回答"E 盘大于 1 GB 的视频""上周改过的报价单""这个目录下的 pdf"。

## 背景
- `FSCTL_ENUM_USN_DATA` 不提供大小与时间，现在 `FileRecord.size/modified` 全为 `None`。
- 方案 A：全量枚举改为直接读 `$MFT`（`FSCTL_GET_NTFS_VOLUME_DATA` + `FSCTL_GET_RETRIEVAL_POINTERS`，
  解析 `$STANDARD_INFORMATION` 与 `$FILE_NAME`/`$DATA` 属性），一次拿到名字、大小、时间，通常也比 ENUM_USN_DATA 快。
- 方案 B：枚举后对每个文件 `GetFileInformationByHandleEx` —— 百万级文件太慢，不采用。
- 增量：USN `DATA_*` 原因只说明变了，不给新大小。变更文件按 FRN `OpenFileById` 查询属性（只读、仅元数据访问），批量合并。
- 节点表已有 `size` / `modified` 字段（`Node::size()` / `modified()`），快照格式已包含它们。

## 要改的文件
- `crates/aifi-ntfs/src/mft.rs`（新）：`$MFT` 记录解析（纯函数，fixup 校验、属性遍历、非常驻属性），手工构造的扇区测试。
- `crates/aifi-ntfs/src/win.rs`：`enumerate_mft`；失败时退回 `FSCTL_ENUM_USN_DATA`。
- `crates/aifi-protocol/src/types.rs`：`FindFilesParams` 新增（全部 `#[serde(default)]`）：
  `under: Option<String>`、`min_size` / `max_size: Option<u64>`、`modified_after` / `modified_before: Option<i64>`、
  `sort: SortBy { Relevance, Modified, Size }`。
- `crates/aifi-query`：过滤在匹配前做（便宜的先做）；`under` 走 `lookup_path` 得到子树根，只扫描子树。
- `crates/aifi-mcp/src/tools.rs`：工具描述补充新参数示例。

## 验收标准 / 测试
- [ ] MFT 解析：常驻/非常驻 `$DATA`、多个 `$FILE_NAME`（DOS 8.3 名要忽略）、fixup 错误、属性越界，都不 panic。
- [ ] VHD 集成测试：MFT 枚举与 ENUM_USN_DATA 得到的路径集合一致，且大小非空。
- [ ] 假卷：`under` + 扩展名 + 大小 + 时间组合过滤结果正确；`sort=modified` 新的在前；分页游标仍然稳定。
- [ ] 协议向后兼容：旧客户端不带新字段时行为不变（测试）。
- [ ] 性能：200 万条目，`under` 限定子树的查询 p50 < 5 ms；全盘子串查询回到 p50 < 20 ms（贴数据）。

## 不在范围内
内容搜索（M11）、文件属性以外的元数据（作者、EXIF 等）。
